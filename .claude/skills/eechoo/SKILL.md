# eECHOo 〰️

把用户的研究"喊"出去，听听一篇论文会传回哪些回声。

eECHOo 不是论文摘要工具。它只回答一个问题：**这篇论文里，哪些具体内容对*这个用户*的*这项研究*有用，有用在哪里？** 摘要谁都能写，有价值的是把论文和用户的研究精确地对上。

## 文件约定

所有文件放在当前工作目录下的 `eechoo/`，档案跟着研究项目走：

```
eechoo/
├── profile.md                          # 用户的研究档案
└── cards/
    └── 2024-smith-label-noise.md       # 每篇论文一份卡片
```

如果用户同时有多个研究项目，用 `profile-<项目名>.md` 区分，开始时问用户用哪一个。

## 流程

### 第 1 步：载入或建立研究档案

先看 `eechoo/profile.md` 是否存在。

**已存在**：用两三句话复述档案要点，问用户是否照此判断、有没有要更新的。如果本次对话里用户已经确认过，就不必再问。

**不存在**：访谈用户，建立档案。

- 在**一条消息**里问完核心问题，不要一问一答拖十轮。同时告诉用户：也可以直接贴 proposal、开题报告或摘要，由你来提取。
- 核心问题：
  1. 领域与子方向
  2. 研究问题 / 目标：具体想回答什么问题？
  3. 核心假设或预期结论（如果有）。有了它才能判断论文是"支持"还是"反驳"
  4. 方法：已经在用的，以及打算用的
  5. 研究对象 / 数据 / 场景：人群、物种、材料、数据集、地区、时间段等
  6. 当前阶段和用途：写综述？找方法？找 baseline？找支持论据？找研究空白？
  7. 什么**不算**相关（排除项）
- 收到回答后，只对真正模糊、会影响判断的地方追问一轮，最多 2–3 个问题。例如"研究机器学习"太宽，必须追问；但不要为了档案完美而反复追问，档案会在使用中不断修正。
- 如果用户只给了一句研究方向就附上了论文，说明他想先看看效果。只要方向本身足够具体（比如"阳光暴露时间与近视的相关性"），就不要拦住他继续问问卷：用最常见的设定补全档案，把补全的条目标成「推定」，直接判断，并在卡片后列出推定项请用户纠正。方向太宽（比如"研究医学"）时仍然要先追问。
- 按 `assets/profile-template.md` 的结构整理成 `eechoo/profile.md`，给用户过目确认。
- 档案里要记下用户提到的关键术语，并补充它们的同义词、缩写和相邻说法。论文常用不同的说法描述同一件事，只做字面匹配会漏掉真正的回声。

为什么档案这么重要：判断"相关"必须有参照物，而**用途**决定了什么算有用。同一个实验细节，对正在找方法的人是金子，对在写综述背景的人只是噪音。

### 第 2 步：读论文

- 用户给了路径就直接读；没给就在当前目录查找 `*.pdf`，列出来让用户选。有多篇时逐篇处理。
- 用 Read 工具读 PDF。超过 10 页的要用 `pages` 参数分段读（每次最多 20 页）。正文、表格、图注都要看，因为关键结果经常只出现在表格或图里。参考文献列表可以跳过；附录先看标题，有相关内容再细读。
- 如果 Read 因为缺少 poppler（`pdftoppm`）而失败，在 macOS 上运行 `swift scripts/extract_pdf_text.swift <论文.pdf> <输出.txt>`，把输出写到临时目录再读。这个脚本用系统自带的 PDFKit 按页提取文字，每页前有 `===== PAGE n / N =====` 标记，可以据此标注页码。它看不到图像，图里的数据只能依靠图注和正文描述。可以顺带建议用户运行 `brew install poppler`，装好后 Read 就能直接读 PDF，包括图表。
- 有些 PDF 提取出来的文字没有词间空格（如 "Myopiainyouthsis"）。引用时把空格补回去，但不要改动任何单词。
- 如果读出来几乎没有文字（扫描版），告诉用户可能需要 OCR，同时尽量根据页面图像继续。
- 边读边在心里列一份论文清单（不必输出）：研究问题、方法、数据/对象、主要结果（带具体数字）、作者自述的局限与未来工作，以及每一项所在的页码、章节、表格或图的编号。

### 第 3 步：判断回声

把论文清单逐条拿去和档案对照。对每一条内容问四个问题：

1. 它呼应档案里的**哪一项**？（研究问题、某个假设、方法、数据，或者命中了排除项）说不出具体是哪一项，就不算回声。
2. 属于哪种回声？（见下方类型）
3. 回声有多强？（见下方刻度）
4. 有哪些差异会妨碍用户直接搬用？（样本、场景、前提假设、尺度等）

#### 回声类型

| 标签 | 含义 |
|---|---|
| 🎯 同题 | 研究问题与用户高度重合：可能是直接竞争的工作，或必须引用的工作 |
| ✅ 支持 | 结果支持用户的假设或预期 |
| ⚡ 冲突 | 结果与用户的假设相反，或动摇了用户方法的前提，写作时必须回应 |
| 🔧 方法 | 方法、模型、实验设计或分析流程可以借鉴 |
| 📊 数据 | 数据集、材料、测量工具或 benchmark 可以用 |
| 🧭 框架 | 理论、定义、分类体系或背景事实，适合引用或用来搭框架 |
| 🕳️ 空白 | 作者承认的局限或提出的未来工作，正好是用户可以填补的空白 |

每条回声只给一个主标签。

#### 回声角度

回声类型说的是这条内容和用户研究的关系；角度说的是它出自论文的哪一部分。有了角度，用户一眼就能知道该去论文哪里找，以及这条证据有多"硬"。

| 角度 | 含义 |
|---|---|
| 问题 | 研究问题、动机、研究目标 |
| 背景 | 引言里的背景事实、文献综述、引用 |
| 方法 | 研究设计、模型、分析流程 |
| 数据 | 样本、数据集、测量工具和测量方式 |
| 结果 | 实证发现：数字、表格、图 |
| 结论 | 作者对结果的解读、讨论中的主张、政策建议 |
| 局限 | 作者承认的局限和提出的未来工作 |

要特别分清"结果"和"结论"：结果是数据显示了什么，结论是作者认为它意味着什么。前者是硬证据，后者是作者的观点，用户引用时分量不同。

每条回声只标一个角度，按主引用所在的位置来定。

#### 回声强度

单条回声用 1–5 级：

- `▰▰▰▰▰` **5 直接命中**：可以原样用于用户的研究，比如直接引用来支撑论点、方法直接照搬，或者是必须回应的冲突
- `▰▰▰▰▱` **4 强回声**：稍作调整就能用
- `▰▰▰▱▱` **3 中等回声**：借鉴价值明确，但场景或对象差异较大，需要用户自己判断能否迁移
- `▰▰▱▱▱` **2 弱回声**：只是同一大领域的背景知识，引不引用都行
- `▰▱▱▱▱` **1 几乎无声**：仅仅是关键词重合

整篇论文的回声强度用**百分比**表示，方便在多篇论文之间比较和排序。按下面的方法计算，保证不同论文之间口径一致：

1. 起点看最强的那条回声：5 级 → 85%，4 级 → 65%，3 级 → 45%。
2. 其余每条 3 级及以上的回声再加分：5 级 +10%，4 级 +8%，3 级 +5%。
3. 总分不能超过最强回声所在档位的上限（见下表）。

| 百分比 | 名称 |
|---|---|
| 85–100% | 直接命中 |
| 65–84% | 强回声 |
| 45–64% | 中等回声 |
| 20–44% | 弱回声 |
| 0–19% | 几乎无声 |

也就是说，**档位由最强的那条回声决定**，其余回声只在档位内拉开差距。整篇论文看的是最强的几条，而不是平均：只要有一处 5 级回声，这篇论文就值得去读那一处；十条 3 级回声加起来，也比不上一条真正的命中。

例：最强一条 4 级，另有一条 4 级、一条 3 级 → 65 + 8 + 5 = 78%，强回声。

没有 3 级及以上回声的论文：只有一些背景层面的弱关联时给 20–44%，弱关联越多越靠上；只是关键词重合时给 0–19%。

#### 校准：别让一切都"有点相关"

最常见的失败是因为关键词重合就判相关，结果每篇都是 3 分，用户无从区分。

- 关键词重合不等于相关。研究蛋白质折叠的人和研究机器翻译的人都用 transformer，但他们之间几乎没有可共享的东西。
- 强度 ≤2 的内容不单独做卡片，最多在"静默区"提一句。
- 两张扎实的卡片，胜过八张凑数的。如果没有回声，就直说"这篇和你的研究基本无关"并给出原因。帮用户省下读一篇论文的时间，本身就是价值。
- 命中排除项的内容直接跳过。

#### 证据

每条回声都必须附上原文引用和位置（页码 + 章节/表格/图编号）。这是用户信任卡片的唯一依据，也能防止你凭印象脑补。

- 引用逐字摘自 PDF，保留原文语言，尽量短，一两句就够。
- 关键证据在表格或图里时，写清楚是哪个表、哪一行、哪个数字。
- 找不到可以逐字引用的原文时，在引用后标注"（转述）"。不要在引号里放论文没说过的话。

### 第 4 步：输出卡片

按 `assets/card-template.md` 的格式生成卡片。

- 卡片用用户的语言写（用户说中文就写中文），原文引用保持论文的原语言。
- 先在对话里完整展示卡片，然后保存到 `eechoo/cards/<年份>-<第一作者姓>-<标题关键词>.md`，文件名全小写、用连字符连接。
- 卡片顺序固定为：标题与作者 → 回声强度 → 回声类型统计 → 各条回声 → 小结（一句话、阅读建议、静默区）。用户最想先知道"这篇值不值得看、有哪几类回声"，紧接着就要看到证据；结论性的话放在证据之后，读起来才有根据。
- 回声按强度从高到低排列。
- "一句话"写的是这篇论文**对用户意味着什么**，不是论文本身讲了什么。
- "怎么用"必须具体到能直接行动：放进用户论文的哪一部分、替换研究流程的哪一步、需要补什么实验或数据。"可以参考该方法"这种话没有信息量。
- 处理多篇论文时，每篇一份卡片文件，最后在对话里附一张简短对比表（论文 / 强度 / 一句话 / 建议），按强度排序。
- 不要在卡片里加入模板之外的小节。

## 档案在使用中修正

用户在过程中纠正你时（"这个其实不相关，因为……"、"我其实也关心 X"），说明档案缺了信息。把修正写回 `eechoo/profile.md` 的"修正记录"，并相应更新正文，然后告诉用户改了什么。这样下一篇论文会判断得更准。
